## **Introduction**

In the previous phases of my StudentHub Cloud Platform project, I worked with AWS networking, IAM, EC2, S3, CloudFront, ECR, ECS, and Route 53.

Until Phase 6, my primary focus was understanding cloud infrastructure and deploying the frontend.

However, StudentHub was still a static website. It could display information, but it did not have a backend to process requests or retrieve student records dynamically.

In Phase 7, I'm taking the next step: building a serverless backend using AWS Lambda and Amazon API Gateway, with Amazon DynamoDB planned for persistent data storage.

The objective is to connect the existing StudentHub frontend with backend services and eventually retrieve real student information from a database.

![](https://cdn.hashnode.com/uploads/covers/67e296ceba50f8341dadb994/bacc5691-310a-4856-aff7-b7f08cb120f2.png align="center")

## Understanding Serverless Architecture :

Serverless computing allows developers to run application code without managing the underlying servers. AWS takes care of infrastructure provisioning, availability, and execution.

For this phase, I'm using the following AWS services and technologies:

**AWS Lambda:** Executes backend JavaScript code.

**Amazon API Gateway:** Receives HTTP requests and connects them to Lambda.

**Node.js:** Runtime used to execute JavaScript in Lambda.

**Amazon DynamoDB:** Database planned for storing student records.

**Amazon S3:** Stores the frontend files.

**Amazon CloudFront:** Delivers the frontend website to users.

![](https://cdn.hashnode.com/uploads/covers/67e296ceba50f8341dadb994/775e9a1d-fa5c-411b-bd7f-ef7df004896c.png align="center")

The overall application flow will be:

Frontend (Browser) → API Gateway → Lambda → DynamoDB

CloudFront delivers the frontend files stored in S3. The browser then sends API requests to API Gateway.

The response follows the reverse backend path:

DynamoDB → Lambda → API Gateway → Browser

At the current stage, DynamoDB has not yet been connected. Lambda is returning sample data to verify the backend integration.

### **What is AWS Lambda?**

AWS Lambda is a serverless compute service that executes code in response to events.

Unlike traditional server-based applications, we don't need to create or maintain an EC2 instance just to execute our backend function.

For StudentHub, Lambda will handle the backend logic whenever API Gateway receives a request.

![](https://cdn.hashnode.com/uploads/covers/67e296ceba50f8341dadb994/5088059d-d222-4b8a-b7e8-bf6e5107f680.png align="center")

## 4\. Step 7.2 – Writing and Testing JavaScript Code

After creating the Lambda function, I moved to the code editor.

I used the `index.mjs` file to write my first backend JavaScript function.

### Lambda function code :

```javascript
export const handler = async (event) => {

    const students = [
        { id: 101, name: "Aditya", course: "Cloud Computing" },
        { id: 102, name: "Rahul", course: "Computer Science" },
        { id: 103, name: "Priya", course: "DevOps" }
    ];

    return {
        statusCode: 200,
        headers: {
            "Content-Type": "application/json"
        },
        body: JSON.stringify({
            message: "StudentHub backend is working!",
            students: students
        })
    };
};
```

### Important concepts

- `handler`: The function AWS Lambda executes.
- `event`: Contains information about the invocation.
- `async`: Allows asynchronous operations.
- `statusCode: 200`: Indicates that the request was successful.
- `JSON.stringify()`: Converts JavaScript data into JSON text.

I created a test event named `studenthub-test` using an empty JSON object `{}`.

The Lambda execution succeeded and returned the sample student records.

**Important:** These records are currently hardcoded inside the Lambda function. They are not stored in a database yet. DynamoDB integration will replace this temporary data source in Step 7.7.

## 5\. Step 7.3 – Creating an HTTP API Using Amazon API Gateway

After successfully testing Lambda, the next step was to expose the backend through an HTTP endpoint.

For this, I used Amazon API Gateway.

### What is API Gateway?

Amazon API Gateway acts as an entry point for HTTP requests.

It receives requests from clients, routes them to the configured backend integration, and returns the response.

I chose **HTTP API** instead of REST API because HTTP API provides the functionality required for this project with a simpler configuration and generally lower cost.

GET is an HTTP method commonly used to retrieve information from a server.

## 6\. Step 7.4 – Connecting API Gateway to Lambda

Creating an API and a route is not enough. We also need to connect the route to the Lambda function.

I configured the Lambda integration using:

studenthub-get-students

I also verified that API Gateway had permission to invoke the Lambda function through its resource-based permissions policy.

### **How does the integration work?**

1. A client sends a GET request.
2. API Gateway receives the request.
3. API Gateway invokes the Lambda function.
4. Lambda executes its handler.
5. Lambda prepares the JSON response.
6. API Gateway returns the response to the client.This established communication between API Gateway and Lambda.

This established communication between API Gateway and Lambda.

## JS :

```javascript
// 1. Existing Project Details functionality

const detailsButton = document.getElementById("details-button");
const projectDetails = document.getElementById("project-details");

detailsButton.addEventListener("click", function () {
  if (projectDetails.hidden) {
    projectDetails.hidden = false;
    detailsButton.textContent = "Hide Project Details";
  } else {
    projectDetails.hidden = true;
    detailsButton.textContent = "Show Project Details";
  }
});


// 2. StudentHub API integration

const loadStudentsButton = document.getElementById("load-students-button");
const studentsStatus = document.getElementById("students-status");
const studentsList = document.getElementById("students-list");

const API_URL = "https://mwnic5mz36.execute-api.ap-south-1.amazonaws.com/api/students";

loadStudentsButton.addEventListener("click", async function () {
  studentsStatus.textContent = "Loading students...";
  studentsList.innerHTML = "";

  try {
    // Send GET request to API Gateway
    const response = await fetch(API_URL);

    // Check whether the request was successful
    if (!response.ok) {
      throw new Error("Failed to fetch student records");
    }

    // Convert JSON response into JavaScript data
    const data = await response.json();

    // Display success message
    studentsStatus.textContent = data.message;

    // Display student records
    data.students.forEach(function (student) {
      const listItem = document.createElement("li");

      listItem.textContent =
        `ID: ${student.id} | Name: ${student.name} | Course: ${student.course}`;

      studentsList.appendChild(listItem);
    });

  } catch (error) {
    studentsStatus.textContent = "Unable to load students. Please try again.";
    console.error("API Error:", error);
  }
});
```

## Understanding CORS While connecting the frontend and backend, I also learned about CORS:

CORS stands for Cross-Origin Resource Sharing.

Our frontend and backend have different origins:

- Frontend: CloudFront distribution.
- Backend: API Gateway endpoint. Browsers restrict cross-origin requests unless the backend allows them.

To enable communication, I configured CORS in API Gateway.

The configuration included:

| Setting | Value |
| --- | --- |
| Allowed origins | CloudFront domain and local development origin |
| Allowed methods | GET, OPTIONS |
| Allowed headers | Content-Type |
| Max age | 300 seconds |
| Credentials | Disabled |

## 9\. Step 7.7 – Integrating Amazon DynamoDB (Upcoming)

So far, our Lambda function returns hardcoded student records.

This is useful for testing, but it is not a practical way to maintain application data.

The next step is to introduce Amazon DynamoDB. What is DynamoDB? Amazon DynamoDB is a fully managed NoSQL database service that stores data in tables.

For StudentHub, we will use it to store student records persistently. Planned implementation

1. Create a DynamoDB table named StudentHubStudents.
2. Understand partition keys and primary keys.
3. Add student records to the table.
4. Configure the Lambda execution role with the required DynamoDB permissions.
5. Modify the Lambda function to retrieve student records from DynamoDB.
6. Test the Lambda function with actual database records.
7. Verify that API Gateway returns the records retrieved from DynamoDB.
8. Test the complete frontend-to-database flow. The important change will be:

**Before:** Lambda returns hardcoded data.

**After:** Lambda retrieves student records from DynamoDB and returns them through API Gateway.

This will make StudentHub a more realistic serverless application.
