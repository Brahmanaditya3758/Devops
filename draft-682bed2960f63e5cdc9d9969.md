Here’s a comprehensive explanation of all the major terms used in Ansible, especially useful for building a solid foundation as a DevOps engineer.

### ***Ansible Server (Control Node) :***

*   This is the machine where Ansible is installed & from which all tasks and playbooks will run.
    
*   It sends commands (playbooks, tasks) to remote hosts using SSH (no agent needed on the remote machines).
    
*   Think of it as the "remote control" for all your target machines.
    

### ***Module :***

*   A unit of code that Ansible uses to perform a specific action. Basically , a module is a command or set of similar commands meant to be executed on the client-side.
    

### ***Task :***

*   A Task is a Section that consists of a single procedure to be completed.
    
*   A single unit of work in a playbook.
    
*   Calls a module with arguments.
    

### ***Role :***

*   A way of Organising tasks and Related files to be later called in a playbook.
    
*   A structured way to organize playbooks, variables, files, and handlers.
    
*   Makes your playbooks reusable and cleaner.
    

### ***Fact :***

*   Information fetched from the client system from the global Variables with the gather-facts Operation.
    
*   Information Ansible automatically gathers about hosts (e.g., IP, OS, memory).
    
*   Accessed via `ansible_facts`.
    

### ***Inventory :***

*   File Containing data about the ansible client server.
    
*   A list of hosts and groups written in INI or YAML format.
    
*   Defines what machines to manage and can include variables.
    

### ***Play :***

*   Execution of playbook.
    
*   A set of tasks executed on a group of hosts.
    
*   It connects the inventory and the tasks.
    

### ***Handler :***

*   A task that only runs when notified i.e, Task which is called only if a notifier is present.
    
*   Used for things like restarting a service only if something changes.
    

### ***Notifier :***

*   Triggers a handler when a task reports a change.
    

### ***Playbook :***

*   It Consists Code in YAML Formate , which describes tasks to be executed.
    
*   A YAML file that contains one or more plays.
    
*   This is the main way to automate complex workflows.
    

### ***Host (Managed Node) :***

*   These are the nodes managed by Ansible .
    
*   They don’t need Ansible installed—just SSH access and Python installed.
    
*   E.g., web servers, database servers, etc.
    

## ***Connecting Ansible Server to Multiple Managed Nodes: Architecture & Setup :-***

In Ansible architecture, communication between the control node (Ansible server) and managed nodes (target machines) is simple, powerful, and agentless. Let’s break down how this connection works and how to set it up.

### **What is the Control Node?**

*   The Control Node is the machine where Ansible is installed.
    
*   It acts as the brain of your automation system.
    
*   Sends instructions (via playbooks or ad-hoc commands) to remote systems.
    

### **What are Managed Nodes?**

*   These are the remote machines Ansible controls.
    
*   No need to install Ansible here.
    
*   They only need:
    
    *   SSH service running.
        
    *   Python installed (default in most Linux distros).
